# v0.1.6 — 2026-07-28

A module can be split across a tree of files and re-exported through a hub, and
the types that come out the other side carry their size. Both halves were
needed: the first landed the chain, the second is why the chain is usable for
anything larger than a function call.

Everything here came out of building a real binding and a real network stack on
top of the previous release, so each item is a place where something the
language already promised did not hold.

## Module chains nest to any depth

A module reference resolved at two levels — `mod.X`, and one special-cased hop
for `mod.sub.X`. Deeper failed, so a hub could not re-export sub-hubs and a
large binding had to sit flat under a single alias.

Every leading component that names a submodule is now consumed, one hop at a
time, so the depth is whatever the import graph has:

```cst
// x11.cst           -> use "xlib.cst" as xlib;
// x11/xlib.cst      -> use "core.cst" as core;
// x11/xlib/core.cst -> fn XOpenDisplay(...) ...

use "x11.cst" as x11;

let is x11.xlib.core.Display as d = x11.xlib.core.XOpenDisplay(cast(*u8, 0));
```

Functions, globals, struct and enum types, type aliases, methods, generic
functions and `fn_ptr` all resolve through the full chain.

One case still does not: an enum **variant** cannot be named through a module
(`m.Color.Blue`), at any depth. Expose a constructor function or a constant.

## A type alias carries the size of the type it names

`type X = OtherModule.Struct` produced a **zero-byte type**. It cost nothing
where the size was merely reported and everything where it was used:

```cst
struct Envolve { c as hub.Coisa; d as i32; }   // sizeof was 4, not 12
```

`c` did not advance the offset, so `d` landed on top of it. As an array element
the stride was zero, so every element shared one address.

The alias was resolved one pass too early — before struct layout ran — and the
zero it copied then froze, because a resolved node is not resolved again. The
name is published in that pass now and the type is resolved in the next one,
in place, so every consumer sees the fix. Chained aliases and aliases of arrays
and pointers come out of the same sweep.

## `only` belongs to the import, not to the module

`use "std/mem.cst" only core as mem;` in one file could break a **different**
file that never mentioned `only` — and the error named the innocent one:

```
Erro: tipo nao definido: 'mem.Bins' (mod_prefix='..._std_string_cst')
```

Two defects. The submodule list was written onto the shared module record, so
one import site narrowed the module for every other. And per-site records were
keyed by alias name, so two files importing one module as `mem` with different
`only` lists shared a record — whichever the compiler reached last answered for
both.

The prefix table now holds only the complete record. Import sites carrying
`only` get their own, keyed by (prefix, only list).

## `CAUSTIC_LIB`

The stdlib was found at `<binary>/../lib/caustic`, or failing that
`/usr/local/lib/caustic`. Neither works for a shape that does not run from
where it was installed: a polyglot `.cse.exe` extracts its native body to a
temp file and execs it, so the guess resolves to `/lib/caustic` and the search
falls through to `/usr/local` — quite possibly an older install, silently.

`CAUSTIC_LIB` is consulted first and used when it names a directory that
exists, so a wrong value falls back rather than failing. The polyglot's launcher
sets it; you can too. It is the first environment variable the compiler reads.

## Standard library

**UDP carries a destination on Windows.** `udp_send` reached `ws2_32`'s `send`,
which has no address argument, so on an unconnected socket the datagram had
nowhere to go; `udp_recv` discarded the sender the same way. Both `sendto` and
`recvfrom` are declared and wired now.

**IPv6.** `Addr6` is parallel to `Addr` rather than a widening of it —
`sockaddr_in6` is 28 bytes and carries a scope id with no IPv4 analogue, so
nothing existing changes. `tcp_connect6`, `tcp_listen6`, `tcp_accept6`,
`udp_bind6`, `udp_send6`, `udp_recv6`. Parsing accepts all three RFC 4291
shapes, including a trailing dotted quad; formatting emits the RFC 5952
canonical form.

**A readiness set that registers once.** `net_poll` hands the kernel the whole
descriptor set on every call. A `Poller` registers it once — epoll on Linux, the
existing `poll`/`WSAPoll` elsewhere, one API either way:

```cst
let is net.Poller as p = net.poller_new(64);
net.poller_add(&p, fd, net.POLLIN_FLAG);
let is i64 as n = net.poller_wait(&p, 1000);
```

Raw `epoll_create1` / `epoll_ctl` / `epoll_wait` are in `std/os/linux.cst` for
callers that want edge-triggered or oneshot and accept being Linux-only.

**`send_all` and `recv_all` retry on `EINTR`.** They treated it as terminal, so
a single signal aborted a whole transfer. They exist to own the loop; they own
this too. The bare `send` and `recv` still surface it.

**The allocator's top bin serves.** A slot is its size class plus an 8-byte
header, so the 65536 class needed 65544 bytes in a 65536 slab and was refused —
a class that existed for nobody, and exactly what a buffer doubling from 32 KiB
asks for. Requests from 32769 up returned null with **no message at all**; only
requests above 65536 printed anything, and it named the wrong limit. Slabs are
sized to hold at least one slot now, and the message is gone rather than
corrected: a library has no business writing to its host's stderr on a failure
the caller already has to check, and there was no way to turn it off.

## `install.sh --from-source` builds the universal image

The linux tarball does not carry `caustic-universal.cse.exe`, so the installer
found nothing to copy and downloaded the released one — `--from-source` handed
back one artifact that was not from that source, silently. It is built now when
`cse` is in `--format`.

## Known

Invoking a polyglot `.cse.exe` bare (letting your shell's ENOEXEC fallback
interpret the stub) can yield a truncated compiler and a corrupt output binary,
with no error. The image cannot carry a `#!` line — it must start with `MZ` for
Windows — so which shell reads the stub is up to the caller. Invoke it as
`sh <path>`.

## Upgrading

Nothing in this release changes an existing program's meaning. `Addr` is
untouched, `only` narrows exactly what its own import site asked for rather than
more, and a type alias that reported zero now reports its real size — code that
worked around the zero by hand should drop the workaround.
